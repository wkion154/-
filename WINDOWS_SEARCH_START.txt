K-IDOL ARCHIVE — 1단계 Windows 브라우저 연결 실험판

검색 후보는 나오지만 미리보기가 robots 오류로 비어 있던 경우:
1. 새 ZIP을 새 폴더에 풀고 START_WINDOWS.bat로 실행합니다.
2. [검색 출처]에서 기존 Kpopping 연결을 유지하고,
   [Kpopping · 사이트 제공 파일 다운로드·미리보기 (검색 후보에 적용)]를 선택해 저장합니다.
   이 옵션은 사이트가 제공한 파일을 실제로 다운로드하므로, 해당 이용 조건을 확인한 경우에만 선택합니다.
3. [인터넷 검색]으로 새 검색을 시작합니다. 기존 사진별 다운로드 거부는 유지합니다.
4. 앱을 닫고 CHECK_SEARCH_WINDOWS.bat를 실행해 새 보고서를 확인합니다.
   provided_preview_enabled=true가 새 옵션을 사용한다는 뜻입니다.

새 경로는 차단된 /api/kpics-image를 호출하지 않고 관측된 주소에 포함된 정확한 CDN 파일만 사용합니다.
CDN의 robots와 출처/사진의 표시·파일 다운로드 권한을 각각 검사합니다. 주소를 추측하거나 크기를 바꾸지 않습니다.
파일은 임시 캐시에 받으며 최대 64MiB/4천만 픽셀 제한을 적용합니다. 영구 보관·분석·AI는 자동 실행하지 않습니다.
사이트 최대 원본을 확인했다는 뜻은 아닙니다. 이 옵션을 끄면 기존의 작은 미리보기 요청 경로를 사용합니다.

통합 검색 검사 (기존 앱 경로 사용):
- 구도·색상을 선택해도 Kpopping 이름 선택에는 인물/그룹 이름만 전달합니다.
  구도·색상 조건은 기존 갤러리 필터에서 유지합니다.
- 접근 차단된 검색에서는 [더 검색]을 멈춥니다. 출처 설정이나 조건을 확인한 후
  [인터넷 검색]으로 새 검색을 시작하면 다시 시도할 수 있습니다.
- START_WINDOWS.bat로 앱을 실행해 검색 출처를 설정한 다음 앱을 닫습니다.
- CHECK_SEARCH_WINDOWS.bat를 실행하고 검사할 인물/그룹 이름을 입력합니다.
- 같은 폴더의 search-pipeline-report.json에서 출처, 검색 배치, 갤러리 결과 수,
  미리보기 디코딩, 실패 이유를 확인합니다. 보고서에는 쿠키·인증 헤더를 넣지 않습니다.
- 기본 검사는 최대 2배치·3개 사진의 미리보기만 처리합니다. 기존 권한을 바꾸거나
  사진을 영구 보관하지 않습니다. 앱이 열려 있으면 잠금 오류를 보고합니다.
- 큰 파일까지 검사하려면 PowerShell에서 아래 명령을 실행합니다:
  .venv\Scripts\python -m app.search_check --query "장원영" --check-files
- 영구 보관까지 원할 때만 위 명령 끝에 --save를 추가합니다. 출처와 사진 양쪽의
  기존 다운로드 권한이 있어야 하며, 미리보기를 큰 파일로 간주해 저장하지 않습니다.
- 이 검사는 실제 검색/라이브러리 처리 경로의 진단입니다. 화면 조작·인물 일치나
  사이트 전체 검색 완료를 보증하지 않습니다. 성공 종료는 요청한 검사 범위에만 적용됩니다.
- 기본 보고서는 %LOCALAPPDATA%\K-IDOL-ARCHIVE\search-reports에도 지정할 수 있습니다.
  명령행 실행은 --output을 생략하면 이 폴더에 고유 이름의 보고서를 저장합니다.

이 파일은 기존 앱에 Kpopping 브라우저 검색 경로를 연결한 소스 실행판입니다.
정식 완료판/EXE가 아닙니다. Windows 실기와 다중 사이트 검색은 아직 검증하지 못했습니다.
Kpopping 하나로 지시서 전체를 완료한 것이 아닙니다.

1. 전체 ZIP을 새 폴더에 압축 해제합니다. 기존 사용자 데이터는 삭제하지 않습니다.
2. Python 3.12와 Microsoft Edge 또는 Google Chrome이 필요합니다.
3. START_WINDOWS.bat를 실행합니다. 첫 실행 때 기본/브라우저 Python 패키지를 설치합니다.
4. 앱의 [검색 출처]를 누릅니다. Kpopping과 Flickr 공개 태그 피드를 따로 선택할 수 있습니다. 출처별 공개 검색/미리보기 이용 조건을 직접 확인한 경우에만 근거를 기록하고 연결을 저장합니다. AI·원본 다운로드 권한은 허용되지 않습니다. 이전 Kpopping 연결 설정은 유지합니다.
5. 먼저 [장원영]을 입력하고 [인터넷 검색]을 누릅니다. 이 인물 목록 URL은 이전 사용자 Windows 보고서에서 확인한 실제 페이지입니다. 사진 속 인물 일치 보증은 아닙니다.
6. Kpopping은 Windows 브라우저를 열고 같은 인물 필터를 유지하며 스크롤을 처리합니다. Flickr는 브라우저나 API 키 없이 공개 태그 피드를 요청합니다. 선택한 두 출처의 요청을 병렬로 실행하고 먼저 받은 후보부터 기존 앱 갤러리에 연결합니다. 이 다중 출처 실동작은 아직 미검증입니다.
   Kpopping은 주소의 ID뿐 아니라 실제 화면의 [Filtering: 이름] 표시도 기다려 확인합니다. 그룹 선택으로 생성된 group/groupName 주소도 같은 방식으로 검사합니다. 표시가 없거나 다른 대상이면 전체 목록을 수집하지 않고 오류를 알립니다. 실제 Windows 그룹 자동 선택은 미검증입니다.
   2026-10-28 실사이트 확인: Flickr는 HTTP 응답과 별개로 현재 robots 정책에서 앱의 공개 피드 자동 접근을 금지합니다. 앱은 해당 출처를 차단하며 다른 User-Agent나 경로로 우회하지 않습니다. 연결을 켰다고 사진 검색 성공을 보장하지 않습니다.
   [스크롤 시 더 검색]이 켜져 있으면 갤러리 하단에서 아래로 스크롤할 때 다음 배치를 요청합니다. 신규 후보가 없으면 자동 요청을 멈춥니다. [더 검색]으로 직접 다시 요청할 수 있습니다. 화면 갱신만으로 연속 요청하지 않습니다.
   검색은 기본 [검색 발견순]으로 표시해 새 결과가 뒤에 추가됩니다. 다른 정렬은 사용자가 선택할 수 있습니다.
7. 로드된 작은 이미지의 더블클릭은 기존 뷰어에서 [미리보기·원본 미확인]으로 표시합니다. 제공된 원본을 확인한 것이 아니므로 고화질 원본 확인 완료로 표시하지 않습니다.
8. 다른 인물/그룹은 검색 입력란과 정확한 선택지를 자동으로 찾으려고 시도합니다. 이 경로는 미검증이며 찾지 못하면 오류로 종료합니다. 아무 사진이나 대신 표시하지 않습니다.
9. Kpopping 제공 파일 확인은 [온라인 → 출처 · URL]에서 출처와 해당 사진의 원본·실측용 다운로드 권한을 각각 확인한 경우에만 실행합니다. 검색 출처 연결만으로 이 권한을 부여하지 않습니다.
   권한이 있고 관측된 이미지 주소에 실제 CDN 파일 주소가 제공되어 있으면, 더블클릭 시 그 주소를 그대로 받아 파일 형식·무결성·크기를 검사하고 기존 뷰어로 엽니다. URL의 크기나 파일명을 바꾸지 않습니다. CDN의 robots도 확인하며 오류·접근 제한 시 우회하지 않습니다.
   뷰어에는 [사이트 제공 파일 · 크기 실측 · 최대 원본 여부 미확인]으로 표시합니다. 실제 크기를 읽어도 사이트가 제공하는 최대 원본이라는 보장은 아닙니다.
   [파일 영구 보관]은 이 파일을 기존 라이브러리로 연결하며 즐겨찾기와 검색 결과 위치를 유지합니다. 미리보기만 있고 큰 파일 주소를 확인하지 못한 경우에는 미리보기를 원본으로 보관하지 않습니다. Flickr 공개 피드는 현재 큰 파일 주소 추출을 지원하지 않습니다.

실제 검색 시도 로그:
%LOCALAPPDATA%\K-IDOL-ARCHIVE\search-reports
실행 결과 JSON에는 검색어·후보 수·페이지·실패 원인만 기록합니다. 로그인 쿠키·헤더·브라우저 프로필은 저장하지 않습니다. 브라우저는 별도 세션으로 실행하며 로그인/CAPTCHA/robots 금지 시 중단합니다.

Flickr의 한계: 검색어를 태그 힌트로 전달하는 최근 공개 피드로 검색어별 최대 20개입니다. 검색어/별칭에 대응하는 태그가 없으면 결과가 없을 수 있습니다. 사이트 전체 검색·과거 페이지 탐색·원본 추출은 지원하지 않습니다. 태그는 사진 속 인물이나 구도가 맞다는 보증이 아닙니다.

미완료: 실제 다중 출처 사진 표시 검증, 그룹/솔로 자동 선택, 원본 확대/추출 확인, Google/Bing/X/Instagram/블로그 등 추가 출처별 접근·구조·이용 조건 검증. 스크롤 추가 요청 UI는 가상 응답으로 검증했으며 실사이트 전체 수집 확인은 아닙니다. 기존 일반 수집기·라이브러리·AI 기능은 보존했습니다. 이미지 분석 전에는 선택한 구도/색상 조건에 일치했다고 확정하지 않습니다.

진행 단계: 총 3단계 중 1단계 진행 중입니다. 이후 2단계(검색 중심 UI·필터·기존 기능 통합), 3단계(자동 갱신·최적화·Windows 실행본 배포)가 남아 있습니다. 현재 1단계의 실제 검색·원본 확인 검증도 완료해야 합니다. 이 ZIP은 Python으로 실행하는 소스 실험판이며 Windows EXE가 아닙니다.
