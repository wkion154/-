# 개발 단계 현황

2026-10-28. 합의한 단계는 총 3개이며 작업 회차와 단계 완료를 구분한다.

| 단계 | 상태 | 완료 기준 또는 남은 범위 |
| --- | --- | --- |
| 1. 실제 온라인 검색·기존 DB 연결 | 진행 중 | 실제 여러 출처에서 인물·그룹·솔로 검색 → 사진 표시 → 다음 결과 → 제공 파일/원본 확인 |
| 2. 검색 중심 UI·필터·기존 기능 통합 | 미착수 | 검색 전후 필터와 분석, 기존 뷰어·저장·즐겨찾기·AI를 실제 결과로 통합 검증 |
| 3. 자동 갱신·최적화·Windows 배포 | 미착수 | 실제 신규 사진 갱신, 대량 결과 최적화, 전체 회귀 및 Windows 실행본 제작·검증 |

현재 1단계의 마무리가 필요하며 **그 이후 단계는 2·3단계, 두 개**다. 완료한 단계는 아직 0개다. 앞선 작업을 두 번 수행했다고 2단계까지 완료한 것으로 기록하지 않는다. 이후 보고에도 현재 단계의 완료 여부와 이후 단계 수를 함께 명시한다.

이번 회차에서 완료한 구현은 사이트가 실제로 제공한 파일 URL의 추출·권한 검사·실측 캐시·기존 뷰어/영구 보관 연결이다. Kpopping의 관측된 /api/kpics-image 주소 안에 제공된 정확한 cdn.kpopping.com/kpics/ 주소만 사용한다. 최대 원본 해상도를 확정하지 않으며 파일명/크기 주소를 합성하지 않는다. 원본·실측용 다운로드는 출처와 사진 양쪽 권한을 확인한다.

작은 미리보기와 제공 파일은 기존 web_revisions에서 같은 이미지의 별도 파일로 관리한다. 제공 파일을 저장해도 기존 검색 결과는 연결된 자산 하나를 표시하며 즐겨찾기와 발견 순서를 유지한다. 사진별 권한을 취소하면 저장본의 보기에도 반영한다. 분석·AI 권한을 자동 허용하지 않는다. 큰 파일 주소를 확인하지 못한 미리보기는 원본으로 저장하지 않는다.

전체 회귀 213개 통과, 35.43초. 마지막 저장 상태 문구/반환 플래그 보강 후 관련 36개도 통과했다. 네트워크 없는 브라우저 fixture와 직접 생성한 소형/대형 PNG를 사용했으며 실사이트 성공 증거가 아니다. `test_provided_files.py`는 주소 검증, 미리보기 권한과 다운로드 권한 분리, 실제 파일 크기 판독, 캐시 변조/권한 취소, 중복 보관 방지, 검색/즐겨찾기 유지까지 검증한다. DB 메타데이터 성능을 같은 가상 10,000개/검색 1,000개 조건으로 재측정한 중앙값은 약 0.03415초였다. 네트워크·이미지 디코딩·Windows UI 시간은 포함하지 않는다.

실사이트 검증의 외부 조건: 현재 클라우드 네트워크는 제한 정책 enforced/custom allowed_hosts 비어 있음 상태다. 저장된 환경 네트워크 초안은 게시/적용되지 않았으며 이 작업에서 권한을 우회하지 않았다. Windows 앱의 실제 다중 출처 표시·제공 파일 접근·그룹/솔로 자동 선택은 미검증이다. 이전 사용자 보고서의 Kpopping 목록 HTTP 200은 관측 증거일 뿐 이번 앱의 전체 흐름을 검증한 것이 아니다.

이번 회차에 기존 8개 검색·조사 호스트를 보존하고 cdn.kpopping.com, live.staticflickr.com, farm1.staticflickr.com~farm9.staticflickr.com을 환경 네트워크 초안에 추가했다. 도구는 status=saved/requires_publish=true를 반환했다. 재개 안내도 현재 구현·단계 상태에 맞춰 저장했다. 기존의 관련 없는 게임 설치 스크립트와 저장소 설정은 수정하지 않았다. 사용자 환경 설정에서 검토·저장·게시한 후 런타임 적용과 실제 요청을 다시 검증해야 한다.

이번 ZIP은 실험용 소스 실행본이다. 실제 Windows EXE 또는 정식 완료판으로 표시하지 않는다. 코드가 더 추가되었다는 이유로 1단계나 후속 단계를 완료 처리하지 않는다.
