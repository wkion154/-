# v0.2.0 · 성능 중심 2단계 보고서

2026-10-28 · Asia/Seoul. **Linux 검증 완료, Windows 빌드/실기 검증은 미완료.**

사용자와 조정한 순서에서 고성능 갤러리·전문 뷰어를 자동 수집보다 앞당긴 단계입니다. 원래 마스터 지시서의 온라인 자동 수집 2단계와 혼동하지 않습니다. 온라인 수집은 이번에 구현하지 않았습니다.

## 1. 구현 및 검증한 기능

- 전체 결과 위치를 즉시 제공하는 가상 갤러리. 필요한 메타데이터를 256건 단위로 읽고 최대 8페이지(2,048건)를 보관합니다. 페이지 이동 때 전체 COUNT를 반복하지 않습니다.
- 빠른 스크롤 중에도 작업을 진행하는 16ms 병합 스케줄러. 화면 밖 썸네일 작업 취소, 오래된 작업 결과 무시, 최대 8개 활성 요청/2개 처리 스레드, 96개 디코딩 썸네일 한도. 캐시 JPEG 디코딩도 백그라운드에서 처리합니다.
- Qt QImageReader 직접 디코딩으로 기존 PIL→RGBA→bytes→QImage 복사를 제거했습니다. 포맷 및 EXIF 회전, 누락 파일 처리를 확인했습니다.
- 뷰어에 128MiB/12항목 디코딩 캐시와 인접 사진 비동기 미리읽기를 추가했습니다. 미리읽기 후보 크기를 제한하고 foreground 작업과 별도 풀을 사용합니다. 현재 표시 이미지 및 디코더 임시 버퍼는 이 캐시 한도에 포함되지 않습니다.
- 뷰어 메타데이터는 최대 768건의 앞뒤 이동 창으로 제한합니다. 갤러리 중간/끝 페이지에서 열어도 이전·다음 탐색이 가능합니다.
- QImage를 직접 참조하는 그래픽 항목이 노출된 영역을 그립니다. 전체 해상도 QPixmap으로 다시 변환하지 않습니다. 이것은 파일 영역 디코딩/타일 디코딩을 구현했다는 뜻은 아닙니다.
- 너비/높이 맞춤, 원본 픽셀 기준 확대율, 전체화면 UI 자동 숨김 및 마우스 이동 복귀. 맞춤 기능은 단정한 메뉴로 묶었습니다.
- 가져오기 완료 및 명시적 새로고침 후 안정적인 이미지 ID를 찾아 기존 선택과 세로 스크롤 기준을 복원합니다. 새 사진이 추가되면 격자 열 위치는 자연스럽게 달라질 수 있습니다.
- v1 DB 스키마·사용자 경로·원본·즐겨찾기를 변경하지 않았습니다. 기존 Alpha 1 회귀 테스트를 유지했습니다.

## 3. 성능 측정

모든 사진은 직접 생성한 샘플입니다. 실제 아이돌 사진 수집 결과나 서로 다른 10만 장의 사진 디코딩 시험으로 표현하지 않습니다. 시간은 명시된 환경의 관측치이며 물리적 디스플레이 FPS, Windows 성능 보장 또는 통계적 품질 보증이 아닙니다.

### 8K 디코더 비교

`scripts/profile_viewer.py` / `viewer-profile-v0.2.json`. 동일한 생성 7680×4320 JPEG/PNG를 각 구현별 독립 프로세스에서 3회 디코딩했습니다. 생성 시간은 제외, RSS는 런타임과 native 할당을 포함합니다. 축소 보간 구현이 서로 다르므로 축소 화질이 수치상 동일하다는 검증으로 해석하지 않습니다. 원본 파일은 수정하지 않습니다.

| 형식·모드 | 기존 중앙값 | 신규 중앙값 | 기존 최대 RSS | 신규 최대 RSS |
|---|---:|---:|---:|---:|
| JPEG 4096px 미리보기 | 700.26ms | 132.47ms | 401.07MiB | 142.66MiB |
| JPEG 전체 해상도 | 294.06ms | 169.01ms | 550.27MiB | 169.30MiB |
| PNG 4096px 미리보기 | 914.38ms | 379.40ms | 400.31MiB | 210.24MiB |
| PNG 전체 해상도 | 520.75ms | 359.65ms | 549.70MiB | 173.93MiB |

### 실제 Qt 가상 목록

`scripts/profile_virtual_gallery.py` / `virtual-gallery-profile-v0.2.json`. 1만/10만 건의 가상 메타데이터가 하나의 생성 JPEG를 별도 해시로 참조합니다. Qt 리스트의 실제 위치 탐색·페이지 보관량을 시험하며, 10만 장의 서로 다른 원본 처리 시험은 아닙니다.

| 결과 수 | 첫 썸네일 | 마지막 페이지 탐색 | 최대 보관 메타데이터 | 관측 이벤트 루프 최대 간격 | 프로세스 최대 RSS |
|---|---:|---:|---:|---:|---:|
| 10,000 | 34.51ms | 4.46ms | 2,048건 | 18.86ms | 108.08MiB |
| 100,000 | 37.27ms | 8.52ms | 2,048건 | 15.07ms | 133.16MiB |

RSS는 같은 프로세스의 누적 high-water mark이며 Qt 내부 레이아웃은 항목 수에 비례합니다. 전체 프로세스 메모리가 항목 수와 무관하다고 주장하지 않습니다.

### 4K 사진 탐색 및 100장 로딩

`navigation-profile-v0.2.json`: 서로 다른 생성 3840×2160 JPEG 4장. 첫 이미지 준비 61.81ms. 미리읽기 후 5회 전환은 모두 캐시 적중이며 화면 scene에 설치하기까지 **2.928~5.282ms**. 디코딩 캐시 약 94.92MiB / 한도 128MiB. 이벤트 루프 p95 간격 12.18ms, 최대 19.34ms. 물리 화면의 표시 완료 시간은 측정하지 않았습니다.

`image-profile-v0.2.json`: 생성 2400×3600 JPEG 100장 가져오기 100건 성공/실패 0건. 첫 썸네일 38.54ms, 이벤트 루프 p95 10.96ms/최대 19.28ms. 가져오기 총 시간은 3068.02ms로, 기존 기록보다 빨라졌다고 주장하지 않습니다.

## 4. 수정한 문제와 남은 한계

- 메타데이터가 무한 누적되던 구조와 뷰어의 누적 페이지 목록을 제한했습니다.
- trailing debounce로 연속 스크롤 중 로딩이 미뤄지던 구조를 throttle로 바꿨습니다.
- 갱신 전 결과가 새 검색/썸네일 요청을 덮어쓰지 않도록 세대·요청 토큰을 검사합니다.
- 실패한 페이지는 명시적 새로고침 전까지 자동 재시도하지 않습니다.
- 파일 영역/타일 디코딩, 이미지 디스크 캐시 용량 자동 정리, ICC/HDR 전문 색상 관리, 장시간 메모리 누수 시험은 미구현/미검증입니다.
- 현재 표시 이미지와 native decoder 버퍼는 캐시 밖 메모리를 사용합니다. 진행 중인 디코딩은 강제 중단하지 못하고 종료 시 끝나기를 기다립니다. 1억 픽셀 안전 한도와 Qt 512MiB 디코더 할당 가드를 유지하되, 실제 100MP 스트레스 시험을 수행했다고 주장하지 않습니다.
- 소규모 인물/소속 조회는 동기식이며 초대형 아티스트 트리의 비동기화는 후속 과제입니다.
- 뷰어 조회는 장기 트랜잭션 스냅샷이 아닙니다. 동시 편집으로 정렬/필터 소속이 바뀌면 이후 페이지 구성이 달라질 수 있습니다.
- 온라인 수집·외부 원본 다운로드·AI 기능은 활성화하지 않았습니다.
- **Windows 빌드, 실제 실행, Windows ZIP, 실제 디스플레이 frame pacing 및 Windows DPI는 미검증입니다.** 기존 Windows 검증 게이트를 닫지 않았으며 완전한 Windows 납품으로 보고하지 않습니다.
