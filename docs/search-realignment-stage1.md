# 방향 수정 1단계 — 미완료 / Wikimedia 제외

사이트 제공 파일 실측·뷰어·영구 보관 연결의 최신 기록과 전체 단계 현황은 [development-status.md](development-status.md)를 참조한다. 현재도 1단계 진행 중이며 이후 2·3단계가 남아 있다.

최신 추가 작업은 아래의 **공개 태그 피드·스크롤·검색 DB 최적화** 절을 참조한다. 이전 절의 수치와 구현 상태는 당시 기록이다. 1단계 실사이트 완료 기준은 여전히 미충족이다.

사용자 추가 지시에 따라 **새 통합 검색에서는 Wikimedia를 제외했다.** 기존 보관 사진/원본/출처 정보는 삭제하지 않는다. 이 작업 중 추가했던 Commons 이름 검색 메서드와 인덱싱 변경도 철회했다. 기존 아티스트 메타데이터·보관 기능은 보존한다.

## 실제 변경

- 검색 세션/결과 연결 테이블을 트랜잭션으로 추가했다. 기존 schema7의 자산·즐겨찾기·AI 결과를 수정하지 않는다.
- 기존 LibraryRepository가 검색 세션 범위를 지원한다. 결과는 기존 web 이미지 ID를 사용하고 저장된 경우 linked_asset_id로 이어진다. 새 사진 저장소나 별도 뷰어를 만들지 않는다.
- 기존 검색창에 인터넷 검색/Enter·구도·미확정 포함·다음 검색 버튼을 연결했다. 기존 로컬 검색/뷰어/필터/AI는 유지한다. 검색 중심 홈 전환은 아직 하지 않는다.
- 확인돼 저장된 이름/별칭과 구도 관련 키워드를 최대 8개로 확장한다. 키워드는 발견 힌트이며 인물 등장이나 구도 조건 일치를 자동 확정하지 않는다.
- 일반 검색 Provider 경계를 만들고, 검토된 HTML 검색 URL 템플릿을 기존 WebService/robots/출처 권한 검사/이미지 파서에 연결했다. 설정은 image_search_templates의 source/template이다. 템플릿은 승인된 출처 도메인만 사용하고 인코딩된 {query}를 넣는다.
- **현재 실제 검증해 기본 활성화한 출처는 없다.** Google/Bing/Kpopping/X/Instagram/Flickr/블로그가 동작한다고 표시하지 않는다. 설정을 적는 것만으로 해당 사이트가 지원되는 것은 아니다.
- 일반 페이지 템플릿 어댑터는 첫 페이지 경로만 연결했다. 사이트별 결과 구조·원본/썸네일 구분·다음 페이지 탐색은 실제 출처 응답과 정책 확인 후 구현해야 한다. 현재 공통 파서는 검색 페이지의 로고나 비관련 이미지를 구별하는 사이트별 로직을 대신하지 않는다.
- 세션 ID로 이전 요청의 늦은 응답을 현재 화면과 분리하고 반복 커서를 차단한다. 한 제공처가 실패하면 다음 검색 계획을 남기며 자동 무한 재시도하지 않는다.

## 실제 외부 검사

과거 Commons 검색은 프록시 403이었고 이제 검색 대상에서 제외했다. 새 조사 대상 Kpopping의 robots.txt도 **HTTP 403**으로 차단됐다. 최신 이용 조건/자동 접근 허용을 확인한 것이 아니며 실제 이미지 수집·갤러리·원본 뷰어를 성공시킨 기록도 없다. `docs/live-checks/search-stage1.json`에 과거/현재 증거를 구분했다.

현재 관리 환경은 제한 정책이 enforced이며 적용된 custom allowed_hosts는 비어 있다. 환경 초안의 네트워크 목적지를 Google/Bing/Kpopping/Flickr/X/Instagram/Naver Blog/Tistory 조사용 8개 호스트로 변경하고 재개 안내를 저장했다. **이 목록은 지원 출처 목록이 아니다. 저장은 적용/게시가 아니다.** 기존 Wikimedia 전용 도메인 초안은 제거했다. 프록시/CAPTCHA/인증/TLS 제한을 우회하지 않는다.

환경 설정에서 초안을 검토·저장·게시한 뒤 적용 상태와 실제 접근을 재검사해야 한다. 그 이후 공식 이용 조건/robots와 실제 검색 응답을 확인한 출처부터 연결한다. 유료 API나 계정 인증은 임의로 진행하지 않는다. 일반 브라우저에 보이는 이미지 주소만으로 분석/저장/AI 사용을 자동 허용하지 않는다.

## 검증 범위

새 검색 테스트는 명시적인 **가상 출처 응답**으로 기존 웹 갤러리 연결, 페이지/중복/세션 격리, 템플릿 도메인/권한 검증, Wikimedia 자동 대체 금지, 한 제공처 실패 시 다른 검색 유지와 Qt UI 연결을 확인한다. 실제 인터넷 검색 성공 증거가 아니다. 전체 회귀는 186개 통과, 36.63초이며 기존 protobuf 경고 2개가 있다. 마지막 설정 오류 격리 보강 후 검색 전용 7개도 재검증했다. 실제 sandboxed Chromium fixture 2개를 포함한 전체 결과는 docs/test-results-search-stage1.xml에 기록했다.

## 사용자 Windows 보고서 이후의 추가 진행

2026-10-28 사용자 보고서에서 Windows 11/Edge의 Kpopping robots와 목록 페이지가 HTTP 200임을 확인했다. 이는 사용자 제공 관측 증거이며 이 클라우드에서 직접 성공한 요청이 아니다. search_submitted=false이므로 자동 이름 검색은 검증되지 않았다. 100개 URL 중 17개 로고/프로필 URL을 제외하고 크기별 주소를 합치면 42개 사진 후보다. 본문은 사이트 메타데이터에 기반하며 인물 일치나 원본 해상도 확정이 아니다. 관측 요약은 docs/live-checks/kpopping-windows-observation.json에 기록했다.

추가 코드:

- Kpopping 관측 파서는 실제 보고서에 등장한 /api/kpics-image 주소만 처리하고, 내포된 CDN 주소를 사진 그룹 키로 사용한다. URL이나 원본 크기를 추측해 생성하지 않는다. 기존 web repository로 메타데이터를 넣는 경로를 테스트했다. 이미지 표시/AI 권한은 자동 허용하지 않는다.
- 추가 스크롤 수집기는 이미 열린 허용된 페이지에서 현재 로드된 이미지 후보를 배치 단위로 읽는다. 누적 사진 키로 중복을 제거하고, 가상 목록에서 이전 항목이 DOM에서 사라져도 기록을 보존한다. 인물 필터가 바뀌거나 All 이동으로 풀리면 중단한다. 새 항목이 없다는 이유만으로 사이트 전체 탐색 완료라고 표시하지 않는다. 사이트 정책 확인은 호출자가 수행해야 한다.
- 검색 실행기는 최대 두 출처를 동시에 요청하고, 빠른 결과를 기존 search_hits에 먼저 반영한 뒤 UI에 통지한다. 출처별 커서와 실패를 분리한다. 차단된 출처는 다른 별칭마다 재시도하지 않으며, 요청 횟수가 적은 출처부터 처리한다. 이 동작은 명시적인 테스트 제공처로 검증했으며 Google/Bing/SNS가 실제 지원된다는 뜻은 아니다.
- Windows 진단 도구는 같은 필터에서 최대 8배치/800후보를 관측하도록 확장했다. 이 제한은 전체 사진 수집 완료가 아니며 게시물 내부의 모든 사진 추출도 아직 미검증이다. 독립 진단 도구는 최종 앱 대체물이 아니다.

전체 196개 테스트 통과(35.79초), 이후 진단 스크롤 연결 및 문구 수정 후 관련 17개 테스트도 통과했다. 테스트 파일은 docs/test-results-search-progress.xml이다. 원본 열기·실제 다중 출처 검색·그룹/솔로 자동 검색·필터 검증·기존 갤러리의 실제 온라인 썸네일 표시까지 확인하지 않았으므로 1단계는 계속 미완료다. 기능을 숨기거나 지원 출처 수를 부풀리지 않고 원래 지시서의 1단계 기준으로 계속 진행한다.

## Windows 앱 연결 실험 경로

기존 앱의 [브라우저 연결]에서 사용자 검토 근거와 공개 메타데이터/제공된 미리보기 범위만 명시적으로 기록한 후 Kpopping 브라우저 어댑터를 활성화할 수 있다. 이 상태는 원본/분석/AI 사용권을 자동 허용하지 않는다. 같은 제공처를 기존 SourceRepository/web_images/gallery_items에서 관리한다.

Windows 전용 자식 프로세스가 Edge/Chrome을 별도 세션으로 실행한다. robots·접근 확인을 수행하고 관측된 인물 목록 경로 또는 화면의 정확한 이름 선택지를 사용한다. 알려진 장원영 경로는 실제 사용자 보고서에 나온 페이지이며 다른 인물 ID를 추측하지 않는다. 현재 다른 이름/그룹 자동 선택은 미검증이다. 다음 배치는 페이지를 다시 열고 앞선 스크롤을 재구성하는 보수적인 방식이며 최적화된 영구 브라우저 세션은 아니다.

후보 URL은 기존 파이프라인으로 실측·표시하고, 작은 이미지의 뷰어 진입은 preview_only로 표시한다. 고해상도 원본을 확인한 것으로 바꾸지 않는다. 요청 취소 시 해당 자식 프로세스 트리만 정리하고 개인 브라우저 프로필은 건드리지 않는다. 검색 시도 요약을 사용자 데이터의 search-reports 폴더에 저장한다.

이 경로의 실제 Windows 성공은 아직 확인하지 못했다. tests/test_kpopping_browser.py는 명시적 가상 브라우저 응답과 직접 생성한 이미지로 기존 갤러리·제공 미리보기 뷰어·권한 분리 연결을 검증한다. 실제 다중 출처 검색 완료 증거가 아니다. WINDOWS_SEARCH_START.txt에 실행 조건과 미완료 범위를 포함해 실험용 소스 실행 ZIP으로 제공한다. 단계 번호나 정식 버전은 올리지 않는다.

## 공개 태그 피드·스크롤·검색 DB 최적화

기존 앱에 Flickr 공개 태그 피드 어댑터를 추가했다. API 키나 계정 로그인 없이 공개 JSON 피드의 실제 media.m 주소를 읽는 코드다. 외부 응답은 아직 검증하지 못했으며 전체 이미지 검색 API로 표시하지 않는다. 검색어별 최근 최대 20개, 검증된 페이지네이션 없음, 태그 일치는 인물·구도 일치 증거가 아니다. 개별 사진 페이지를 기준으로 기존 web_images에 연결해 다른 별칭으로 같은 사진이 나와도 동일 ID를 재사용한다. 제공처별 robots·도메인·권한 검사를 적용한다. 원본 주소를 생성하거나 AI 권한을 자동 허용하지 않는다.

[검색 출처]에서 Kpopping과 Flickr를 각각 활성화/비활성화할 수 있다. 출처별 근거를 기록하고 기존 사진별 거부 기록은 보존한다. 두 출처가 켜진 경우 기존 검색 실행기로 병렬 요청하고 먼저 받은 후보부터 갤러리에 반영한다. 검색 전용 페이지는 일반 HTML 자동 갱신 작업에서 제외해 다른 경로로 잘못 수집하지 않는다. 실제 관심 검색어 갱신은 아직 미완료다.

갤러리 하단에서 아래로 스크롤할 때 다음 배치를 요청하도록 연결했다. 동시에 한 검색 작업만 진행하고, 모델 갱신이나 위치 복원만으로 요청이 반복되지 않는다. 신규 후보가 없으면 자동 요청을 중단하고 수동 [더 검색]을 남긴다. 기본 검색 발견순은 세션 등록 순서를 사용해 새 후보를 뒤에 추가하며, 저장본으로 연결된 이미지도 같은 검색 위치에서 찾는다. 미리보기 전용 파일은 기존 뷰어에서도 계속 preview_only로 표시한다.

Kpopping 브라우저를 재실행해 스크롤 위치를 재구성할 때 중간 DOM도 읽도록 수정했다. 이전에 본 사진 키를 커서에 보관해 중복을 건너뛰고 가상 목록에서 이미 사라진 중간 사진을 놓치지 않게 한다. 브라우저를 다시 여는 비용은 여전히 있으며 영구 세션 최적화를 완료한 것은 아니다. All 전환으로 인물 필터가 풀리거나 다른 인물로 바뀌면 중단한다.

검색 세션 ID 목록을 먼저 집계하고 gallery_items 기본 키로 조회하도록 DB 질의를 변경했다. 가상 이미지 10,000개/검색 후보 1,000개에서 기존 중간 구현의 첫 256행+개수 조회는 12.294초였다. 변경 후 같은 조건 5회는 0.0337~0.0398초, 중앙값 0.03635초다. 네트워크·썸네일 디코딩·Windows UI 시간을 포함하지 않는 Linux SQLite 메타데이터 측정이다. 재현 스크립트는 scripts/profile_search_results.py, 기록은 docs/search-results-profile.json이다.

전체 회귀 206개 통과(34.87초, 기존 protobuf 경고 2개). 마지막 검색 전용 페이지 자동 갱신 제외 보강 후 관련 52개도 통과했다. 샌드박스 Chromium 테스트는 네트워크 없는 fixture 2개다. 새 Flickr 테스트는 가상 JSON과 직접 생성한 이미지로 주소 검사·중복·사진별 거부 유지·기존 미리보기 뷰어·원본/AI 권한 분리를 검증한다. 실사이트 검색 성공을 증명하지 않는다.

현재 클라우드 네트워크는 제한 정책 enforced/custom allowed_hosts 비어 있음 상태다. 추가된 Flickr 경로를 포함한 실제 다중 출처 사진 표시·인물/그룹/솔로 자동 검색·고해상도 원본 감상은 미검증이다. Google/Bing/X/Instagram/블로그/언론사 수집기를 이번에 구현한 것이 아니다. 단계 2로 완료 판정을 넘기지 않는다. 업데이트된 실험용 소스 ZIP에 코드·테스트·성능 기록을 함께 제공한다.
