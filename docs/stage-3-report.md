# v0.3.0 · 자동 수집·갱신 엔진 개발판 보고서

2026-10-28 · Asia/Seoul. **독립 구현/회귀 검증 완료. 실서비스 연결은 외부 네트워크 제한으로 미완료이며 자동 수집은 비활성입니다.**

## 1. 구현한 기능

- Wikidata 구조화 데이터의 신규 후보 탐색/식별자 상세 조회, Commons 카테고리의 사진 목록/파일 메타데이터 Provider를 구현했습니다. 이름만으로 인물을 병합하거나 사진을 인물에게 자동 귀속시키지 않습니다.
- 외부 식별자, 검토 후보, 갱신 대상, 원격 사진 인덱스, 파일별 출처/이용 조건, 재개 가능한 작업 큐를 별도 테이블로 저장합니다. 원격 메타데이터/썸네일을 로컬 원본인 것처럼 등록하지 않습니다.
- 아티스트 탐색/상세 갱신/사진 목록/원본 보관을 독립 작업으로 처리합니다. 중복 작업 키, cursor 체크포인트, 재시작 복구, 요청 간격, 429/5xx 제한 재시도와 Retry-After, 401/403 차단 상태, 수동 재시도를 구현했습니다. 한 작업의 재시도 대기가 다른 작업을 막지 않습니다.
- 조건이 충분한 **일부** 신규 그룹/인물은 근거가 첨부된 구조화 claim을 기준으로 등록할 수 있도록 구현했습니다. 기존 ID 연결, 이름 충돌, 불확실한 유형/활동 정보는 검토로 남깁니다. 운영상 2012년 기준은 공식 세대 판정이 아닙니다. 솔로 활동을 여성 아티스트라는 이유만으로 추정하지 않습니다.
- 기존 이름·소속·성별 등 로컬 수정은 자동으로 덮어쓰지 않고, 외부 이름/소속/인물 정보 변경을 제안으로 보존합니다. 남성을 포함한 전체 멤버의 외부 소속 후보도 보존하지만 미확인 관계를 확정하지 않습니다.
- 온라인 관리 화면에 등록 검토/갱신 대상/온라인 사진/작업 상태를 연결했습니다. 필요한 썸네일만 받으며 원본은 사용자가 선택할 때 받습니다. 알려진 CC BY/BY-SA/CC0/PD URL, 저작자 표시와 추가 제한을 보수적으로 검사하되, 이는 AI 사용권이나 인격권 허가가 아닙니다.
- 원본은 부분 파일로 스트리밍한 뒤 크기·제공처 SHA-1(있는 경우)·자체 SHA256·디코딩 가능 여부를 확인합니다. 기존 파일은 다른 내용이면 덮어쓰지 않습니다. 파일 개정본은 페이지 ID+내용 해시로 구분합니다.
- 같은 원격 사진은 여러 갱신 대상에 연결하고, 원본은 SHA256으로 기존 로컬 자산과 중복 제거합니다. 카테고리 소속만으로 인물 등장을 확정하지 않으며, 개인 연결은 명시적 확인이 있어야 수행합니다.
- DB v1→v2는 SQLite backup 후 트랜잭션으로 추가 테이블을 생성합니다. 기존 DB/즐겨찾기/파일/설정 경로는 보존하며, 이전 버전 앱의 v2 DB 열기는 지원하지 않습니다.

## 3. 해결한 문제

- 소스 메타데이터 작업마다 메인 갤러리를 초기화하지 않고, 실제 로컬 등록 변화 때만 선택/스크롤을 보존하며 갱신하도록 분리했습니다.
- 주기적 UI 스냅샷에서 대형 raw JSON을 옮기지 않고 200개 원격 행/300개 검토 후보로 제한했습니다. source/local-asset 조회 인덱스도 추가했습니다.
- 원본 재사용 때도 명시적인 인물 연결이 적용되도록 하고, 원격 대상 연결을 재검증합니다.
- 파일 개정본이 바뀌어도 이전 원본을 새 원본이라고 간주하거나 덮어쓰지 않습니다.
- 닫은 온라인 대화상자의 runner 연결과 늦은 작업 콜백, 닫은 뷰어의 scene 이미지 잔류를 정리했습니다.

## 4. 외부 차단 및 남은 문제

### 현재 확인된 네트워크 차단

이 작업에서 읽기 전용 Commons siteinfo 요청은 다음 결과였습니다.

`URLError: Tunnel connection failed: 403 Forbidden`

현재 환경 상태는 running / network enforced이며, 런타임 custom allowlist는 비어 있고 observed revision은 1입니다. 다음 **7개 호스트**는 환경 설정의 **편집 초안에만 저장**했습니다. 저장 도구는 `status=saved`, `requires_publish=true`를 반환했습니다.

- commons.wikimedia.org
- upload.wikimedia.org
- www.wikidata.org
- query.wikidata.org
- www.mediawiki.org
- foundation.wikimedia.org
- doc.wikimedia.org

기존 package_managers 프리셋/저장소/설치·시작 스크립트는 변경하지 않았습니다. **초안 저장은 실행 환경 반영/게시가 아닙니다. 환경 설정에서 검토·저장 후 게시해야 합니다.** 네트워크가 반영된 뒤 정책 원문/robots/API/응답/vocabulary/실제 썸네일·원본 검증을 재개해야 합니다. 현재는 단순 접근 실패를 자격증명 부족으로 오인해 토큰을 요청하지 않았습니다. 공개 API 외의 로그인·차단 우회·다른 서비스 수집은 하지 않았습니다.

`source-check-v0.3.json`은 실제 최초 차단 관측과 정책 URL 목록을 기록한 **offline/not_run** 보고서입니다. 정책을 다운로드·검토한 성공 기록이 아닙니다. `scripts/check_sources.py`는 이후 실제 원문과 vocabulary를 확인하는 도구이며, 원문 다운로드 자체를 정책 승인으로 간주하지 않습니다.

### 미검증/미완료 범위

- 최신 정책과 실제 API/파일을 확인하지 못해 활성화 조건을 충족하지 않았습니다. API 어댑터가 존재한다는 이유로 실제 자동 갱신이 작동한다고 보고하지 않습니다.
- Wikidata/Commons의 K-pop 커버리지는 불완전하며 모든 신규 혼성그룹/솔로/멤버 이력의 자동 발견을 보장하지 않습니다. 불확실한 인물/소속·기간·이름 변경은 검토가 필요합니다. 실제 데이터 커버리지/장기 누락률/재시도 품질은 미검증입니다.
- 미확인 사진의 성별/등장 인물을 판정하지 않습니다. 실제 남성만 등장하는 사진을 신뢰성 있게 자동 제외하는 분류기는 아직 없으며, 그런 사진을 여성 인물 갤러리에 자동 귀속하지 않습니다.
- 원격 인덱스는 별도 온라인 화면입니다. 기존 메인 가상 갤러리는 로컬 참조/보관된 원본을 표시합니다. 온라인 썸네일과 로컬 자산의 단일 통합 그리드는 후속 UI 과제입니다.
- 네트워크 원본은 256MiB, 썸네일은 8MiB 한도입니다. 진행 중인 소켓 읽기는 즉시 강제 중단하지 못하므로 종료가 설정된 timeout까지 기다릴 수 있습니다. 디스크 캐시 자동 용량 정리는 미구현입니다.
- 중단된 프로세스가 남긴 오래된 `.part` 파일의 자동 청소, 동시 다중 앱 인스턴스의 lease/heartbeat 조정, 네트워크를 포함한 장시간 메모리 시험은 남아 있습니다. 현재는 단일 앱 인스턴스의 재시작 복구를 대상으로 합니다.
- Windows 빌드/실제 실행/Windows ZIP은 계속 **미생성·미검증**입니다. AI 분석/업스케일은 미구현이며 제공처의 AI 사용 허가도 부여하지 않았습니다.
