# 7-4 · 배포 준비와 최종 회귀 검증 · v0.7.4 개발판

Windows 검증을 실행할 수 있는 빌드/CI와 배포 무결성 검사를 추가했다. **이 환경은 Linux이며 Windows EXE를 빌드/실행하지 않았다. 정식 출시 또는 Windows 실기 검증 완료판이 아니다.**

## 변경

- `build_windows.bat`는 사용자 `.venv`와 분리된 `build/windows-venv`를 매번 새로 만든다. 이 생성 환경은 재빌드 시 삭제한다. 고정 기본 의존성으로 테스트 후 PyInstaller 기본 EXE를 생성하고, 해당 EXE의 자동 실행 검사까지 통과해야 ZIP을 만든다. 기본 EXE는 선택 CV/AI 패키지를 제외한다. AI 포함 Windows 배포본으로 표시하지 않는다.
- `--smoke-test <보고서 경로>`는 별도 임시 라이브러리에서 한글 경로의 직접 생성 사진을 등록한다. 실제 갤러리/썸네일, 즐겨찾기, 설정 저장과 SQLite quick_check를 확인하고 JSON을 저장한다. 사용자 데이터 경로를 사용하지 않고 온라인/자동 분석을 끈다. 검증은 offscreen이므로 실제 모니터 품질 확인과 다르다.
- `.github/workflows/windows-validation.yml`은 Windows 2022/Python 3.12에서 수동 실행하도록 구성했다. 테스트 XML, EXE 실행 검사 JSON, Windows ZIP/체크섬을 아티팩트로 보관한다. 원격 저장소에 게시하거나 CI를 실제로 실행하지 않았다.
- 모든 배포 ZIP에 버전/종류/파일 크기/SHA256을 기록한 RELEASE-MANIFEST.json을 넣는다. `scripts/verify_package.py <zip>`은 전체 목록·CRC·해시를 검증하며 경로 탈출, 중복/대소문자 충돌, 심볼릭 링크와 예상 밖 파일을 거절한다. 이는 파일 무결성 확인이며 코드 서명을 제공하는 기능은 아니다.

## 실제 실행 결과

Linux Python 3.12.14에서 **179 passed**, 35.22초. 실제 샌드박스 Chromium fixture 2개와 실제 CPU 업스케일/얼굴 참조 테스트를 포함한다. protobuf의 Python 3.14 관련 경고 2개가 있고 검증 Python은 3.12이다. [테스트 원문](test-results-v0.7.4.xml).

신규 배포 테스트는 정상/변조 ZIP, 안전하지 않은 경로·대소문자 충돌·목록 불일치를 확인했다. 실행 검사는 별도 프로세스의 다른 작업 디렉터리에서 수행하며 사용자의 데이터 경로에 놓은 파일이 그대로 유지되는지도 확인했다. [실행 검사 JSON](release-smoke-v0.7.4.json)은 `platform: Linux`로 기록되어 있다.

[실제 Qt 가상 갤러리 측정](virtual-gallery-profile-v0.7.4.json):

| 합성 메타데이터 | 첫 썸네일 | 마지막 페이지 이동 | 메타데이터 최대 상주 | 누적 최대 RSS |
|---|---:|---:|---:|---:|
| 1만 건 | 82.42ms | 9.87ms | 2,048건 | 117.48MiB |
| 10만 건 | 72.29ms | 28.29ms | 2,048건 | 150.43MiB |

직접 생성한 JPEG 한 장을 서로 다른 메타데이터가 참조하는 Linux offscreen 측정이다. 실제 10만 장 디코딩, 물리 화면 FPS, 장시간 사용이나 Windows 성능을 입증하지 않는다. AI 모델 메모리를 포함한 수치도 아니다.

## Windows에서 남은 확인

1. Windows에서 `build_windows.bat` 또는 수동 CI를 실행해 테스트·실제 EXE smoke JSON·ZIP 검사 결과를 확보한다. 현재 체크아웃은 원격 CI 실행 결과가 없다.
2. 실제 데스크톱에서 한글/공백 경로, 100/125/150/200% DPI, 다중 모니터, 전체화면·복귀, 키보드/드래그 동작을 확인한다.
3. 외부 원본/NAS/이동식 디스크 연결 해제·재연결, 쓰기 권한/디스크 부족, 잠긴 파일, 비정상 종료 후 복구를 실기 검증한다. 기존 자동 테스트가 이 전체 실기 조합을 대신하지 않는다.
4. 선택 AI의 Windows 소스 설치, 실제 GPU/4080 SUPER와 VRAM/OOM, 다양한 실제 인물의 참조 품질과 장시간 사용을 확인한다. 기본 EXE에는 AI가 없다.
5. 실제 수집은 기존 Wikimedia 프록시 403 문제와 최신 제공처 정책 확인이 남아 있다. 이번 단계에서 네트워크 정책을 변경하거나 실사이트 수집을 검증하지 않았다.

마지막 세 단계의 개발판 기능과 배포 자동화는 준비했으며, Windows/GPU/실사이트·다양한 인물 품질에 대한 최종 검증은 계속 열린 항목이다.
