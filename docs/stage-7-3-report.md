# 7-3 개발판 · 실제 CPU 업스케일과 비교 · v0.7.3

## 납품 범위

실제 FSRCNN 2배/4배 모델 실행, 원본 좌표 기반 3중/좌우/슬라이더 비교, 별도 캐시·영구 보관과 얼굴 내부 참조 보조 실험 기능을 구현했다. 단순 크기 변경을 신경망 실행으로 표시하지 않는다. 얼굴 랜드마크로 방향·눈/입 상태와 결과 구조 변화를 검사한다. **실험 기능을 포함한 개발판이며 정식 품질 검증을 마친 범용 인물 참조 모델은 아니다.** 다양한 각도·시기·가림/표정의 인물 데이터셋 평가와 RTX 4080 SUPER/Windows 검증은 남아 있다.

## 사용

1. 소스 환경에서 기본 `requirements.lock` 설치 후 `python -m pip install -r requirements-upscale.lock` 실행. Linux Python 3.12에서 검증했다. 얼굴 참조 모드는 `python -m pip install -r requirements-reference.lock`로 선택 MediaPipe 패키지도 설치한다. 패키지에 동봉된 얼굴 모델만 사용한다.
2. 사진 정보 패널의 **AI 업스케일 · 비교**, 또는 뷰어의 **AI 업스케일** 버튼으로 연다. 온라인 후보는 영구 보관 후 출처·사진별 권한을 확인해야 한다. 이 기능이 원본을 내려받지 않는다.
3. 로컬 사진은 **선택 사진 권한**에서 근거와 함께 로컬 분석, AI 복원 입력, 결과 저장·이용을 각각 기록한다. 출처 허용과 해당 사진 허용이 모두 필요하다. 참조 사진도 세 권한이 모두 필요하다.
4. 2배/4배와 모드를 선택한다. 참조 자동 선별은 확인된 한 인물 연결과 고해상도 후보가 필요하다. 후보가 없거나 얼굴 크기·정렬·방향·눈/입 상태·선명도가 부적합하면 보류 이유를 표시한다. 일반 모드로 몰래 바꾼 뒤 참조 결과라고 표시하지 않는다.
5. 마우스 휠로 확대하고 드래그로 이동한다. 세 결과는 동일한 원본 좌표와 확대율을 공유한다. **원본 100%**는 원본 픽셀 기준이며 각 결과의 크기가 달라도 대응 위치가 같다. 슬라이더와 전체화면을 지원한다.
6. **원본 별도 저장 / 일반 결과 보관 / 참조 결과 보관**은 각기 별도 파일을 영구 저장소의 `upscale` 하위에 만든다. 결과 PNG와 설정·모델·입력/참조 해시·권한 근거·평가 메타데이터 JSON을 함께 저장한다. 원본 저장은 원본 바이트를 그대로 복사한다.
7. **표시 결과 캐시 비우기**는 현재 표시한 일반/참조 결과만 지운다. 영구 보관 파일과 원본을 지우지 않는다. 전체 AI 캐시의 자동 용량 정리는 아직 없다.

## MODE A · 실제 모델

Saafke/FSRCNN_Tensorflow의 고정 커밋 `6a4812c4ef1c4f5947d79beafa32a05a6eb4a94d`에서 x2/x4 가중치를 확인했다. 두 파일은 약 80KB이며 수정하지 않고 소스에 동봉한다. 공식 고정 URL로 다시 받아 SHA256이 동일한지 확인했다. 모델별 지원 배율을 그대로 사용하며 x3은 제공하지 않는다. [모델 명세](upscale-model-manifest.json), `app/models/fsrcnn/LICENSE`와 NOTICE에 출처를 기록했다. 저장소의 Apache-2.0 LICENSE와 README를 보존했다. upstream이 밝힌 학습 데이터는 T91/General100이며 해당 데이터의 권리 관계를 별도로 감사했다는 뜻은 아니다.

OpenCV dnn_superres의 실제 FSRCNN CPU 추론을 실행한다. 패키지 잠금은 NumPy 1.26.4 / opencv-contrib-python 4.11.0.86이다. 모델/출처 사진을 런타임에 자동 다운로드하거나 외부 서버로 전송하지 않는다. FSRCNN은 작고 CPU에서 실행 가능한 기반 모델로 선택했으며 Real-ESRGAN/SwinIR과 얼굴 품질 비교를 통해 최종 선정한 모델은 아니다. 디테일은 추정이며 실제 원본 정보의 정확한 복구로 표시하지 않는다.

## MODE B · 얼굴 내부 참조 보조 · 실험

확인된 동일 Person ID와 권한이 있는 저장 사진 후보 중 기준보다 픽셀 수가 큰 사진을 최대 8개 시도한다. 여러 확인된 인물이 연결된 사진은 제외한다. 양쪽 촬영일이 알려진 경우 180일 넘게 떨어진 후보는 제외한다. 촬영일을 모르는 사진의 시기를 추정해 채우지 않는다.

MediaPipe 0.10.21의 오프라인 Face Mesh 468점 모델로 두 사진 모두 한 얼굴이 검출되는지 검사한다. 얼굴 최소 가로·세로 40px, 눈 간격 12px를 요구하고 잘린 얼굴은 보류한다. 참조의 눈 간격은 기준의 1.35배 이상이어야 한다. 얼굴 방향 근사값, 입 벌어짐/폭, 좌우 눈 열림과 입 위치를 비교한다. 안정적인 얼굴 점으로 부분 아핀 정렬을 계산해 충분한 inlier, 작은 구조 오차와 회전 범위를 확인한다. 부적합한 얼굴은 신경망 실행 전에 제외한다. 두 얼굴 모델 파일은 번들 패키지의 SHA256을 확인하며 명세에 추가했다.

참조 영상은 원본 중심 좌표로 정렬한다. 얼굴 윤곽을 안쪽으로 줄인 마스크의 **내부에만** FSRCNN 결과의 휘도 고주파를 0.15 강도로 보조하고 변화는 ±6으로 제한한다. 마스크 밖은 일반 신경망 결과의 RGB 바이트를 그대로 복사한다. 옷/배경을 참조 영상으로 덮어쓰지 않는다. 얼굴 내용·조명 상관과 참조의 추가 선명도 근거를 확인한다. 결과를 다시 얼굴 모델에 통과시켜 랜드마크·눈/입 상태 변화가 큰 경우 채택을 보류한다. 마스크 밖 불변 여부와 구체적인 검사 수치를 메타데이터로 남긴다.

이 기능은 **실제 FSRCNN 신경망 + 랜드마크 정렬/제한적 참조 디테일 보조**이다. 별도로 학습된 범용 참조 조건부 생성 모델은 아니다. 얼굴 랜드마크 검사는 신원 인식이나 정체성 보존 증명이 아니며, 가림·화장·광원·머리카락/손이 얼굴 안에 겹친 경우 마스크가 의미적으로 완벽하다고 보장할 수 없다. 얼굴 밖을 보호해도 얼굴 내부의 추정 디테일이 사실이라는 뜻은 아니다. 큰 표정/각도 차이와 심한 저해상도는 보수적으로 거절한다. 과감한 얼굴 재생성이나 표현/헤어스타일 교체 기능은 제공하지 않는다.

실제 얼굴 실행 검증은 NASA의 Eileen Collins 사진(scikit-image 공식 표본)의 512px 원본/256px 축소본 한 쌍으로 진행했다. 공식 scikit-image 문서가 이 사진을 public domain으로 명시하는 근거와 SHA256을 `tests/fixtures/astronaut-provenance.json`에 보관했다. NASA/피사체의 보증이나 실제 K-pop 사진 평가를 뜻하지 않는다. 같은 사진의 다른 해상도 테스트이므로 서로 다른 촬영 사진의 정체성 보존 정확도를 입증하지 않는다.

## 반응성과 데이터 보존

복원 전용 자식 프로세스 하나만 허용한다. OpenCV/OpenBLAS/OMP 스레드를 제한하고 Linux nice / Windows 프로세스 우선순위 설정을 사용한다(Windows 동작은 미검증). CPU가 기본이다. OpenCV CUDA 장치·실행 대상 진단을 통과한 환경에서만 CUDA 선택을 활성화한다. CUDA 네이티브 오류가 나면 CPU로 한 번 재시도하고 실제 실행 장치와 사유를 기록·표시한다. 현재 환경은 CUDA 장치 0개이며 pip OpenCV 빌드에 CUDA 대상도 없다. GPU 실동작/VRAM은 측정하지 않았고 OOM 재시도 경로는 오류 주입 테스트로 확인했다. 갤러리·뷰어 이벤트 루프에서 모델을 실행하지 않는다. 타일은 입력 128px, 겹침 16px이며 각 타일의 중앙부만 결과에 넣는다. 전체 추론과 타일 결과 차이가 최대 1 단계 이내인지 실제 x2/x4 테스트로 검증했다.

입력/참조는 최대 1,600만 픽셀, 파일 최대 128MiB, 결과 최대 1,600만 픽셀로 제한한다. 예를 들어 4배는 입력 약 100만 픽셀까지 가능하다. 투명 이미지의 복원은 지원하지 않는다. 배율을 낮추거나 별도 파일을 준비하라는 오류를 제공하며 입력을 몰래 축소하지 않는다. 시도 전체에 5분 제한을 두고 실패/메모리 부족/모델 오류는 앱 밖 프로세스의 실패로 처리한다. 프로세스 전체의 엄격한 RAM 상한은 아니다. 기존 백그라운드 이미지 분석과는 독립 작업이므로 CPU 작업이 완전히 하나뿐이라는 뜻도 아니다.

취소는 UI 이벤트를 유지한 채 자식 프로세스 terminate, 필요시 kill로 정리한다. 닫기 시에도 작업을 취소하고 완료 콜백 후 창을 닫는다. 작업용 임시 디렉터리를 삭제한다. 앱 재실행 시 실행 중이던 기록을 interrupted로 남기며 자동으로 AI 작업을 재개하지 않는다. 사용자가 다시 실행할 수 있다.

입력은 작업 전 해시를 검사하면서 별도 스냅샷으로 복사한다. 모델·설정·배율·전처리 버전·원본/참조 해시·확인 인물로 캐시 키를 만든다. 재사용 시에도 현재 권한·입력 상태와 결과 SHA256을 검증한다. 모델 처리 뒤 입력 파일 상태와 등록 해시를 확인하고, 결과 게시 트랜잭션에서 권한과 인물 연결을 다시 확인한다. 권한 철회·인물 연결 해제는 게시/조회/보관을 차단한다. 영구 보관본도 자동 삭제하지 않는다.

기존 스키마 7의 extension_records를 사용해 작업 상태와 결과 메타데이터를 저장한다. 사진/종류/생성일 인덱스를 추가했으며 자산/원본 레코드를 복원 결과로 덮어쓰지 않는다. 최근 결과 조회/재사용은 사진별 최근 24건으로 제한한다. 오래된 결과를 자동 삭제하지 않는다. 외부 파일 전체 감시 기능은 없으며 결과 재조회는 마지막 검증 해시와 파일 경로·크기·수정시각을 기준으로 한다. 이미 화면에 표시한 결과를 권한 철회 즉시 지우는 실시간 감시 기능은 없다.

## 검증

Linux Python 3.12.14에서 **177 passed**, 32.32초. 실제 sandboxed Chromium fixture 2개 포함. [테스트 XML](test-results-v0.7.3.xml). protobuf의 Python 3.14 관련 deprecation 경고 2개가 있으며 현재 검증 버전은 3.12이다.

신규 21개 테스트는 실제 x2/x4 추론과 타일 경계, 실제 자식 프로세스 실행/취소, GUI 이벤트 루프 유지와 닫기, 동일 좌표 비교, 원본 보존/결과 영구 저장/캐시 삭제 분리, 참조 자동 선별·얼굴 방향/표정/크기 부적합 참조 거절·마스크 밖 불변, 권한 분리·실행 중 철회·원격 출처 권한 세탁 방지, 인물 연결 해제, 변경 원본/투명 이미지/과대 결과 거절, 모델/결과 해시 검증, 오류 후 임시 파일 정리, 중단 기록 복구, 촬영 시기 제한과 CUDA 실패 시 CPU 재시도 경로를 확인했다.

[일반 합성 차트 측정](upscale-profile-v0.7.3.json)과 [실제 얼굴 표본 측정](face-upscale-profile-v0.7.3.json)을 분리했다. 얼굴 표본은 NASA/scikit-image 사진의 256×256 축소본과 512×512 원본 참조이다. 전체 시간은 프로세스 시작·입력 검증·모델 로드를 포함한다.

## 남은 검증과 후속 범위

7-3의 실험 기능을 정식 인물 참조 복원으로 승격하려면 다양한 촬영 조건의 실제 검증과 정체성/시선 보존 평가, 가림에 강한 영역 분할, 모델 품질 비교가 필요하다. CUDA 경로는 진단과 오류 복구를 구현했지만 실제 GPU/VRAM 실험은 남아 있다. 이번 환경에서 검증한 실행 장치는 CPU이다. 기본 Windows 빌드는 선택 CV 패키지를 제외하므로 AI 기능이 포함된 Windows 배포판을 납품한 것이 아니다. Windows 소스 실행/EXE와 장시간 실사용은 7-4에서 검증해야 한다.

기존 7-1의 실제 Wikimedia 연결 및 수집 검증은 프록시 403 문제로 미완료 상태를 유지한다. 이번 작업에서는 사진 사이트 연결을 재시도하거나 클라우드 정책을 변경하지 않았다.
