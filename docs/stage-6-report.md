# 6단계 기반 · 성능·복구 안정화 · v0.6.0 Alpha 6

대규모 탐색, 수집/검사 병행 및 실패 복구를 보강했습니다. **6단계의 독립적으로 검증 가능한 안정화 범위이며 정식 출시 후보(RC)는 아닙니다.** 실제 사이트 수집·AI 복원·Windows 실기 검증은 계속 남아 있습니다.

## 구현한 변화

| 영역 | 동작 |
| --- | --- |
| 취소 작업 | Qt에는 실제 실행할 작업만 전달. 취소된 대기 작업을 정리하고 신호/콜백 참조도 해제 |
| 동시 처리 | 서로 다른 출처의 네트워크 최대 2개와 로컬 분석 1개. 같은 출처의 네트워크 중복 실행 차단 |
| 절약 설정 | 백그라운드 수집을 출처 1개씩으로 줄일 수 있음. 실행 중인 작업은 완료 후 새 한도 적용 |
| 전경 우선 | 뷰어/연관 사진 감상과 스크롤 중 새 자동 작업 대기. 실행 중/직접 요청한 작업은 유지 |
| 출처 분리 | 자동 작업의 출처별 순번, 실패·재시도 대기 시간 영속 저장, 다른 출처는 계속 진행 |
| 요청 간격 | 호스트별 간격·Retry-After를 독립 HTTP 클라이언트와 리다이렉트가 공유 |
| 중단 복구 | 커서/입력 개정본 보존, 실행 토큰으로 이전 실행의 늦은 완료 상태 변경 차단 |
| 단일 앱 잠금 | 데이터 폴더별 동시 앱 실행 방지. 정상 종료/프로세스 사망 확인 후 잠금 해제·복구 |
| 유사 검사 | 기존 1만 건 조회 제한을 밴드 인덱스와 배치·커서 처리로 교체 |
| DB 중복 등록 | 동시에 같은 SHA256을 등록해도 자산 하나와 양쪽 인물 연결 유지 |

명시적 수동 요청은 해당 요청 큐를 따릅니다. 자동 출처 순번은 벽시계가 같은 순간에도 공정하도록 증가하는 논리 순번을 사용합니다. 서버 대기 시간은 작업 재시도/앱 재시작으로 건너뛰지 않습니다. 긴 호스트 대기는 작업 스레드를 점유하지 않도록 재시도 상태로 돌립니다. 런타임 호스트 간격은 프로세스 안에서 공유하고, 출처별 대기 시간은 DB에 영속 저장합니다.

앱 시작점이 잠금을 얻은 뒤 마이그레이션/복구를 실행합니다. 실행 토큰은 큐 상태 소유권을 보호하며 모든 외부 작업의 exactly-once 실행을 보장하는 것은 아닙니다. 다운로드 무결성·원자적 게시·SHA256 자산 식별 등 기존 재실행 보호도 유지합니다. 자동 갱신을 꺼 둔 경우 복구된 작업도 직접 요청/재시도해야 합니다.

기존 사진·인물·그룹·즐겨찾기·출처 권한·수동 관계를 유지합니다. 논리적 동일 파일 등록은 중복 자산을 만들지 않지만, 여러 출처에서 이미 생성된 디스크 원본 사본을 일괄 통합·삭제하지는 않습니다.

## 대량 유사 특징 인덱스

기존 dHash64를 13/13/13/13/12비트의 5개 밴드로 나눠 인덱스를 만들었습니다. 4비트 이하 차이라면 적어도 한 밴드가 같으므로 후보를 찾은 뒤 정확한 비트 거리를 검사합니다. 이는 해시 공간의 후보 탐색 성질이며 실제 사진 중복/인물 인식 정확도를 보장하지 않습니다.

각 밴드의 정렬된 제한 목록만 합쳐 큰 단색 후보 집합을 매 배치마다 전부 메모리에 모으지 않습니다. 한 배치는 최대 512건, 이어가기 커서는 작업 큐에 기록합니다. 첫 배치에서 허용된 파일의 해시·픽셀을 확인하고 특징을 계산하며, 이어지는 배치는 입력 개정본이 같은지 확인한 뒤 저장된 특징을 재사용합니다. 같은 파일을 페이지마다 다시 디코딩하지 않습니다. 현재 후보 개정본과 양쪽의 분석 권한도 확인합니다.

단색 등 저정보 이미지가 서로 비슷한 해시를 만들어 후보가 폭증할 수 있어 한 검사에서 제안은 최대 200개로 제한하고 UI에 표시합니다. 이때 전체 사진 간 관계를 모두 저장하지 않습니다. 자동 삭제·병합·인물 귀속은 수행하지 않습니다. 인덱스의 페이지 열람에는 이전의 1만 건 자르기가 없지만, 실제 제안은 이 자원 한도를 따릅니다.

## 측정

Linux Python 3.12 / PySide6 6.8.3, Qt offscreen. 측정용 도형/JPEG·사전 계산한 합성 해시와 가상 메타데이터를 사용했습니다. 외부 사이트나 실제 AI 모델을 실행하지 않았습니다.

| 합성 특징 수 | 인덱스 후보 조회 | 후보 수 | 정확 거리 통과 / 전수 비교 정답 |
| --- | --- | --- | --- |
| 1만 건 | 1.01ms | 15개 | 10 / 10 |
| 10만 건 | 1.50ms | 88개 | 20 / 20 |

위 수치는 **SQL 후보 조회 시간**입니다. 이미지 다운로드·디코딩·특징 계산·권한 확인·전체 분석 완료 시간을 포함하지 않습니다. 테스트의 정답은 해시 거리 기준이며 실제 사진의 의미적 관련성이 아닙니다. 10만 건으로 늘리는 합성 특징/인덱스 추가 입력은 2,217.26ms였습니다.

취소 교체 요청 1만 개를 실행 중인 작업 뒤에 보냈을 때, 유지된 작업은 실행 중 1개 + 최신 대기 1개였습니다. 완료 후 교체 작업의 살아 있는 약한 참조는 0개였습니다. 전체 앱에서 모든 종류의 메모리 누수가 없다는 증명은 아닙니다. 명시적 저장 작업은 취소 교체와 구분해 모두 유지합니다.

10만 건 Qt 가상 갤러리에 합성 수집 2개와 인덱스 검사 1개를 병행하고 20개 위치로 이동한 결과:

- 이벤트 루프 최대 간격 **16.12ms**, p95 **14.35ms**.
- 위치 이동 전체 **198.22ms**, 메타데이터 상주 최대 **2,048건**.
- 해당 측정 프로세스 RSS 최고치 **132.21MiB**.

[부하·인덱스·작업 참조 원자료](stability-profile-v0.6.json). 수집 작업은 로컬에서 대기하는 합성 I/O이며 실제 사이트 네트워크나 실제 PNG 대형 디코딩 부하가 아닙니다. 한 생성 JPEG를 여러 해시 레코드로 참조한 가상 사진을 사용했으므로 고유 사진 10만 장/실제 화면 FPS 결과가 아닙니다.

별도 기존 갤러리 측정의 10만 건 마지막 페이지 이동 **13.12ms**, 첫 썸네일 **47.40ms**, 이벤트 루프 최대 간격 **13.24ms**, RSS **146.78MiB**. [원자료](virtual-gallery-profile-v0.6.json). 기존 연관 후보 검색은 같은 합성 조건에서 **84.75ms**로 측정됐습니다. [원자료](related-profile-v0.6.json). 단일 실행의 변동을 포함하며 장치별 성능 보증이나 실제 모니터의 끊김 없음 보장으로 해석하지 않습니다.

스레드/큐와 표시 캐시는 제한하지만 네이티브 DNS·소켓·디코더의 즉시 취소나 전체 프로세스 메모리 상한은 보장하지 않습니다. 실행 중인 작업은 전경 우선으로 전환해도 완료를 기다립니다. 여러 대형 이미지의 디코딩 버퍼는 표시 캐시 한도 밖에 있으므로 절약 모드를 선택할 수 있습니다. GPU/VRAM 및 AI 타일 처리는 모델 엔진이 미구현인 현재 범위에 포함하지 않았습니다.

## 회귀·복구 검증

**123개 통과, 12.43초, 실패/건너뜀 0.** 실제 Chromium 샌드박스의 외부 통신 없는 DOM fixture 2개 포함. [전체 결과](test-results-v0.6.xml).

신규 검증 범위:

- 최신 요청 3,000개를 실행 작업 뒤에 교체하고, 신호 참조 1,000개가 해제되는지 확인.
- 명시적 저장 순서 유지, 취소된 대기 작업 실행 금지, GUI 스레드 콜백 전달.
- 출처별 동시 획득·공정한 자동 순번·복구 후 이전 실행 토큰 거부.
- 재시작/수동 재시도 시 서버 대기 유지, 클라이언트·리다이렉트 간 공유 간격.
- 1만 건을 넘는 동일 해시 후보 페이지, 무작위 해시의 전수 비교 대조, 개정본·권한·취소 검사.
- 512건 배치 뒤 커서 복구와 디코딩 재사용, 저정보 후보 200개 상한.
- 두 출처 수집+분석 중 Qt 이벤트 처리, 감상 우선, 1개 처리량 모드의 수동 작업 보존.
- 동일 파일 동시 등록, 실제 자식 프로세스 강제 종료 뒤 라이브러리 잠금 복구.
- 스키마 v4→v5 백업/전체 DDL 롤백/기존 특징 인덱스 채우기와 명시적 거부 유지.

가상 시간을 7일 이상 진행한 240개 작업/4개 합성 출처에서 3페이지 커서, HTTP 429, 취소, 10회 이상 재시작을 섞어 모두 완료하고 로컬 파일·즐겨찾기를 보존하는 테스트도 통과했습니다. 실제 일주일 동안 앱을 운영한 내구성 시험은 아닙니다.

## 사용·마이그레이션·배포

온라인 → **작업 상태**에 출처 열을 추가했습니다. [화면](stability-ui-v0.6.png)은 합성 출처와 상태 기록이며 실제 수집 성공 화면이 아닙니다. 설정 → **백그라운드 수집**에서 절약/균형을 선택할 수 있습니다. 기존 사진 중심 차콜 UI와 연관 필름스트립은 유지했습니다.

DB 스키마 v5. 기존 v1/v2/v3/v4는 SQLite backup API로 고유 백업을 남긴 뒤 원자적 이전합니다. 기존에 계산한 특징만 256건 단위로 읽어 인덱스에 채우며 새 픽셀 분석이나 권한 허용을 하지 않습니다. 업데이트 전 앱을 닫고 데이터 폴더를 별도 백업하세요. 이전 앱은 새 DB를 열 수 없습니다.

새 패키지/모델을 설치하지 않았고 의존성 잠금을 유지했습니다. 소스 ZIP과 SHA256을 제공하며 ZIP CRC와 압축 해제 후 가져오기/빈 DB 생성을 검증합니다. Windows 실행 파일은 생성/실행 검증하지 않았습니다.

## 남은 출시 조건

실행 환경의 추가 허용 도메인이 없어 이전 Wikimedia 7개 도메인 초안은 여전히 실행 정책에 반영되지 않았습니다. 환경 설정에서 검토·저장·게시 후 실제 정책/API/파일 검증이 필요합니다. 기존 일반 HTML/DOM 어댑터의 실제 사이트 검증도 남아 있으며 X·Instagram·Flickr·Kpopping 등 후보를 정상 지원 출처로 새로 활성화하지 않았습니다.

구도·색상/영역/의상·배경 의미 분석, AI 업스케일/인물 참조 복원, 실제 정체성 보존 평가, 3중 비교, 원격·로컬 통합 사진 벽, 디스크 캐시 정리, 실제 장기 수집과 Windows DPI/입력/빌드·배포 검증이 남아 있습니다. 이번 안정화 결과를 앞 단계의 미완료 기능이나 최종 출시 검증이 완료된 것으로 취급하지 않습니다.
