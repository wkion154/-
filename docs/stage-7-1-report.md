# 7-1 · 실제 수집 연동/통합 갤러리 · v0.7.1 개발판

통합 갤러리와 원본 보기/보관 흐름을 구현·검증했습니다. **실제 사이트 연동 검증은 프록시 403으로 미완료이며 7-1 전체 완료로 보고하지 않습니다.** 실제 수집 성공이나 최신 정책 검토를 합성 데이터 테스트로 대체하지 않습니다.

## 실제 연결 결과와 필요한 조치

기존 프록시/TLS를 유지한 공개 Commons API 요청 1회를 실행했습니다. 결과는 `Tunnel connection failed: 403 Forbidden`입니다. 이미지/대량 요청은 하지 않았습니다. [실제 진단 기록](live-checks/stage-7-1.json).

환경 도구로 확인한 상태:

- 실행 환경: 제한 정책 적용 중, 사용자 추가 허용 도메인 0개.
- 저장된 설정 초안 revision 3: 아래 7개 도메인 존재, 저장 자체는 확인됨.
- 초안의 네트워크 규칙이 실행 환경에는 적용되지 않음. [상태 기록](live-checks/network-state-7-1.json).

| 저장된 도메인 | 용도 |
| --- | --- |
| commons.wikimedia.org | Commons API·출처·robots |
| upload.wikimedia.org | 제공 썸네일/원본 |
| www.wikidata.org | 인물/그룹 공개 API·정책 |
| query.wikidata.org | 신규 후보 탐색 |

| foundation.wikimedia.org | 이용 조건·User-Agent 정책 |

**사용자 조치: 환경 설정에서 이 초안을 검토·저장한 뒤 환경을 게시해야 합니다.** 앱의 이미지 이용 권한과는 별개의 네트워크 적용 절차입니다. 다른 프로젝트의 설치/시작 스크립트나 네트워크 프리셋은 수정하지 않았고 새 도메인도 추가하지 않았습니다.

이 절차의 근거는 읽은 [Cloud Environment Runtime SKILL.md](skill://plugin_connector_1p_c5b7d5df5d7081918f2c4be5a633ed5d/cloud-environment-runtime/SKILL.md)의 다음 명시적 요구입니다:

> Configuration changes require the environment configuration workflow and its user review.

같은 스킬의 [네트워크 지침](skill://plugin_connector_1p_c5b7d5df5d7081918f2c4be5a633ed5d/cloud-environment-runtime/references/networking.md)도 다음과 같이 규정합니다:

> An explicit destination-policy denial requires the supported configuration workflow; do not bypass the proxy to reach a blocked destination.

따라서 프록시를 우회하거나 초안 저장을 실제 적용으로 간주하지 않았습니다. 도구 호출의 자동 승인 거절이 아니라 실행 환경의 목적지 제한으로 발생한 403입니다. 초안 적용 뒤 실제 정책/API/robots/식별자·라이선스·User-Agent 조건을 확인하고, 허용된 실제 사진의 썸네일/보기/보관/갱신·실패 복구까지 검증해야 7-1을 완료할 수 있습니다. 현재 그 검토를 완료했다고 기록하거나 Commons 자동 수집을 임의 활성화하지 않았습니다.

## 구현한 사용 흐름

| 기능 | 현재 동작 |
| --- | --- |
| 통합 목록 | 로컬 등록 사진 + Web/Commons 후보를 같은 가상 그리드에 표시 |
| 보기 선택 | 로컬 + 온라인 / 로컬만 / 온라인 후보만. 마지막 모드 저장 |
| 필터/정렬 | 기존 출처·그룹·인물·즐겨찾기와 등록/발견·이름·실측 해상도 정렬 |
| 미확인 후보 | 출처 링크, 제공처 선언과 미실측 표시. 원본 URL을 로컬 파일처럼 다루지 않음 |
| 썸네일 | 현재 출처/파일 권한을 재확인하고 화면 주변만 처리. 일반 페이지 원본을 임의 대체 다운로드하지 않음 |
| 원본 열기 | 선택한 항목만 비동기 해석·무결성 확인 후 보기 캐시로 표시. 주변 원격 원본을 미리 받지 않음 |
| 영구 보관 | 별도 요청을 큐에 넣어 저장. Commons는 검증된 보기 캐시를 재사용해 중복 다운로드 방지 |
| 사진 연결 | 실제 등장 확인만 명시적으로 기록. 이름 언급/Commons 인물 카테고리는 자동 인물 귀속 아님 |
| 보관 전환 | 즐겨찾기·확인 연결 전달, 안정 ID로 선택 복원. 연결된 온라인 타일은 등록 사진과 중복 표시하지 않음 |
| 내용 변경 | 이전 확인/즐겨찾기를 이력에 보존하고 새 원격 개정본에서 초기화. 저장 원본·연결은 유지 |

확인된 남성만 연결된 원격 후보는 기본 숨김이며 즐겨찾기와 기존 파일을 삭제하지 않습니다. 여성/미확인 인물이 연결되면 현재 확인 상태를 반영합니다. Commons 그룹 카테고리 분류와 실제 등장 인물 확인은 구분합니다.

표시·원본·분석·AI 권한은 기존처럼 독립적입니다. 로컬 등록 표시가 추가됐다고 원격 출처 조건을 우회하지 않습니다. 원본 보기 권한을 확인하지 못한 항목은 오류/출처 정보로 남기고 탐색을 계속할 수 있습니다. 캐시가 확보되어 있고 현재 권한/개정본/체크섬이 일치하면 URL 접근 실패와 별개로 그 캐시를 재사용할 수 있습니다.

보기만으로 영구 등록하지 않습니다. 이미 외부 참조로 등록한 파일과 같은 내용을 영구 보관하면 같은 자산 ID를 유지하면서 보관 복사본 경로로 전환합니다. 원래 외부 파일은 건드리지 않고 `asset_path_history`에 위치를 남깁니다. 기존 영구 원본을 자동 교체·삭제하지 않습니다. 동일 SHA가 알려졌지만 아직 보관본과 연결되지 않은 온라인 북마크는 즐겨찾기 유실을 막기 위해 숨기지 않습니다. 보관 시 실제 동일 자산에 연결합니다.

메타데이터 재수집이 로컬에서 해제한 즐겨찾기를 다시 켜지 않도록 전달은 최초 보관 연결 때만 수행합니다. 변경된 파일에는 이전 인물 확인을 그대로 복사하지 않습니다. 실제 복원/AI 분석/색상·구도 분석은 이번 변경에 포함하지 않았습니다.

## 구조와 성능

스키마 v6에 정렬 가능한 통합 메타데이터와 원격 확인/즐겨찾기/보기 캐시·이력 테이블을 추가했습니다. 기존 자산 ID와 원격 Provider ID는 유지합니다. SQL 트리거가 실제 변경을 반영하고 최초 발견 시각을 유지하므로 단순 메타데이터 갱신으로 사진 순서가 뒤섞이지 않습니다.

초기 통합 쿼리에서 SQLite가 OR 조건 뒤 전체 정렬을 택하는 성능 저하를 발견했습니다. 고정된 정렬 인덱스와 페이지 하위 쿼리로 바꿔 페이지를 정한 뒤 경로/권한을 결합합니다. 조회는 백그라운드, 메타데이터 최대 2,048건/썸네일 최대 8개 대기·96개 표시 캐시를 유지합니다.

Linux Qt offscreen에서 한 생성 JPEG를 여러 가상 해시로 참조했습니다. 혼합 목록의 온라인 5만 건은 이용 권한 없는 메타데이터 링크여서 이미지 요청은 0회입니다. 실제 썸네일 5만 장·실제 사이트 지연·고유 사진 10만 장·실제 모니터 FPS 측정이 아닙니다. 수치는 단일 실행의 변동을 포함하며 전체 이미지 로드 시간이나 끊김 없음 보증이 아닙니다.

새 메타데이터는 제한 주기로 갱신하고 안정된 배치 레이아웃 후 스크롤을 복원합니다. 사용자 휠/스크롤 조작은 복원 작업보다 우선합니다. 긴 출처/이용 안내는 오른쪽 정보 패널 안에서 스크롤됩니다. 전경 우선 실행과 기존 네트워크/분석 한도는 유지합니다. 네이티브 디코더·파일 해시 I/O의 즉시 취소나 전체 메모리 절대 상한은 보장하지 않습니다.

## 테스트·마이그레이션·산출물

최종 Linux 회귀 결과: **140개 통과**, 실패/건너뜀 0. 실제 Chromium 샌드박스의 외부 통신 없는 DOM 테스트 2개 포함. [전체 결과](test-results-v0.7.1.xml). 새 테스트는 통합 모드·권한 없는 후보의 무요청, 실제 픽셀/선언값 분리, 보기/영구 보관 구분, 체크섬/만료 캐시, 명시적 인물 확인·혼성 표시, 즐겨찾기/선택 보존, 개정본 이력, 외부 참조 보관 전환, 원격 미리 받기 방지, 메타데이터 재수집의 수정 보존 및 v5→v6 롤백/백업을 검증합니다.

기존 v1~v5 DB는 SQLite backup API로 고유 백업 후 원자적으로 이전합니다. 현재 메타데이터를 통합 인덱스로 채우지만 이미지 다운로드나 권한 부여는 하지 않습니다. 업데이트 전 앱을 닫고 전체 데이터 폴더를 별도 백업하세요. 이전 앱으로 새 DB를 열 수 없습니다.

## 남은 7-1 완료 조건

환경 초안 게시 → 실제 정책/API·파일 조건 검토 → 허용된 실제 수집/원본 보관/재갱신·실패 복구 검증 순으로 마쳐야 합니다. 새 실사이트 Provider를 정상 지원으로 추가하지 않았습니다. 일반 HTML/DOM 어댑터는 합성 검증 상태이고 X·Instagram·Flickr·Kpopping·공식/언론/팬 사이트는 여전히 검토 후보입니다. 이 외부 완료 조건을 남겨 둔 채 7-2의 이미지 분석까지 완성됐다고 간주하지 않습니다.
