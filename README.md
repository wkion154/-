# K-IDOL ARCHIVE · Alpha 5 · v0.5.0 개발판

Python/PySide6 기반 로컬 인물 사진 라이브러리입니다. 사진 중심 차콜 UI, 그룹·인물 관리, 비동기 갤러리와 기본 뷰어를 제공합니다. Eagle의 라이브러리/정보 패널 구조와 Lightroom의 감상 흐름을 참고한 독립 구현입니다. 상표·아이콘·사진·소스는 복제하지 않았습니다.

## 이번 버전과 현재 제한

이번 버전은 **5단계의 연관 사진·인물 참조 후보 검색 기반**입니다. 연관 사진 목록과 뷰어 필름스트립, 근거가 보이는 관계 확인/제외, 권한별 참조 후보 필터를 추가했습니다. AI 복원 모델 실행은 구현하지 않았습니다. 이전 단계의 멀티 소스 수집 기반과 출처·URL 관리도 유지합니다. 출처별 어댑터, 독립 권한, HTML/DOM 이미지 후보 추출, 실측 해상도와 개정본 보관을 지원합니다. 출처 목록에 있다는 이유만으로 해당 사이트 수집이 지원되는 것은 아닙니다.  **현재 클라우드에서는 Wikimedia 요청이 프록시 403으로 차단되어 최신 정책/API 및 실제 사진 수집을 검증하지 못했습니다. 따라서 실제 자동 수집은 비활성 상태이며, 완성된 온라인 서비스로 보고하지 않습니다.** Windows 실행/배포 검증도 남아 있습니다.

- Wikidata 신규 후보 탐색/정보 갱신, Commons 카테고리 사진 목록 Provider.
- 출처·저작자·파일별 라이선스·촬영일/업로드일을 분리한 원격 메타데이터 인덱스.
- 근거가 충분한 일부 신규 아티스트만 자동 등록하는 보수적 규칙. 불확실한 혼성그룹/솔로/활동 이력, 같은 이름과 식별자 충돌은 검토 대기.
- 앱 실행 중 주기적 갱신, 영속 작업 큐·중단 재개·제한 응답 재시도·작업별 실패 분리.
- 선택한 썸네일만 캐시하고, 원본은 사용자가 선택할 때만 내려받아 크기·해시·디코딩 검증 후 등록.
- 사진 카테고리만으로 인물 등장을 확정하지 않습니다. 인물 연결에는 사용자의 명시적인 확인이 필요합니다.
- 기존 가상 갤러리/128MiB 뷰어 캐시/미리읽기/선택·스크롤 복원 유지. 뷰어를 닫을 때 표시 이미지까지 해제하고 종료된 작업 관리자에 늦은 응답이 전달되지 않도록 수정했습니다.

## 실행

Python 3.12 권장 (테스트: Linux Python 3.12.14, PySide6 6.8.3, Pillow 11.2.1).

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.lock
.venv\Scripts\python -m app.main
```

Linux 개발:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m app.main
```

데스크톱 세션이 필요합니다. GUI 테스트는 `QT_QPA_PLATFORM=offscreen`으로 가능합니다. Linux 기본 Qt xcb 실행에는 배포판별 X11/xcb 시스템 라이브러리가 필요할 수 있습니다. `python -m app.main`을 프로젝트 루트에서 실행하세요.

## 사용

- 왼쪽 ARTISTS의 **＋**에서 그룹·인물·솔로를 추가합니다. 항목 우클릭으로 이름과 별칭을 수정합니다.
- **멤버 연결 관리**에서 여러 그룹 소속 및 혼성그룹의 기본 갤러리 대상을 관리합니다. 소속 전체와 갤러리 대상은 별개입니다.
- **사진 가져오기**에서 다중 파일 또는 폴더를 선택합니다. 하위 폴더까지 검사하며 심볼릭 링크 폴더는 따라가지 않습니다.
- 기본은 **외부 파일 참조**입니다. 원본 복사를 선택하면 영구 저장소에 해시 이름으로 보관합니다. 원본을 수정·재압축하지 않습니다.
- 가져오기 때 선택한 그룹·인물은 전체 선택 사진에 적용됩니다. 확인한 인물만 연결하세요. 사진 정보 패널에서도 추가 연결할 수 있습니다.
- 중복은 SHA256으로 판정합니다. 같은 사진을 재등록하면 파일을 중복 저장하지 않고 그룹·인물 연결을 추가합니다.
- 파일명·그룹명·인물명·별칭 검색, 등록일/파일명/해상도 정렬, 즐겨찾기를 지원합니다. 촬영일을 추정해 채우지 않습니다.
- 더블클릭하면 뷰어: 휠 확대, 드래그 이동, 좌우 방향키, Esc 복귀, F11 전체화면. `Ctrl+0` 화면 맞춤, `Ctrl+1` 원본 픽셀 로드, `W` 너비 맞춤, `H` 높이 맞춤. 전체화면에서 조작부는 잠시 후 숨겨지며 마우스를 움직이면 다시 나타납니다.
- 기본 뷰어는 긴 변 4096px 미리보기입니다. **원본 픽셀**에서 전체 해상도를 비동기로 읽습니다. 미리보기 여부를 화면에 표시합니다. 최대 1억 픽셀 안전 한도가 있습니다. 애니메이션은 첫 프레임, 다중 페이지 TIFF는 첫 페이지만 지원합니다. 색상 관리/HDR/전문 타일 뷰어는 후속 단계입니다.
- 누락 파일은 오류 상태로 표시합니다. **원본 다시 연결**에서 동일 SHA256 파일로 복구합니다.
- `Ctrl+K` 검색, `Ctrl+O` 파일 가져오기. 좁은 창에서는 정보 패널이 자동으로 접히며 버튼으로 펼칠 수 있습니다.

## 데이터 보호

Windows 기본 데이터: `%LOCALAPPDATA%\K-IDOL-ARCHIVE`. Linux: `~/.local/share/K-IDOL-ARCHIVE`. 개발/테스트는 비밀값이 아닌 `K_IDOL_DATA_DIR`로 격리 가능합니다.

DB, 설정, 썸네일, 영구 원본, 로그를 분리합니다. 설정에서 캐시와 영구 저장 경로를 바꿀 수 있으며 기존 파일은 자동 이동/삭제하지 않습니다. 캐시 정리 UI는 아직 제공하지 않습니다. DB는 외래키·트랜잭션·WAL 및 버전 마이그레이션을 사용합니다. 이름은 기본키가 아니며 동일 이름은 자동 병합하지 않습니다. 현재 동명이인은 구분되는 표시 이름으로 등록합니다. **업데이트 전에 앱을 닫고 데이터 폴더를 백업하세요.**

## Windows 배포

Windows Python 3.12에서 `build_windows.bat` 실행. 테스트 → PyInstaller 폴더형 빌드 → 의존성 라이선스 수집 → ZIP 및 SHA256 생성 순서입니다. 결과 경로: `dist/K-IDOL-ARCHIVE_v0.5.0_Windows.zip`.

**현재 Linux 환경에서는 Windows 실행 파일을 생성하거나 실기 검증하지 않았습니다.** 빌드 스크립트를 제공하지만 Windows 성공을 보증하지 않습니다. 소스 ZIP은 `python scripts/package.py`로 생성합니다. 사용자 데이터는 배포 폴더 밖에 저장됩니다.

## 온라인 연결 준비와 사용

1. 앱 상단 **온라인**에서 등록 검토, 갱신 대상, 온라인 사진, 작업 상태를 확인합니다.
2. 신규 아티스트 탐색 또는 Wikidata Q ID 조회를 요청할 수 있습니다. Q ID는 이름만으로 다른 사람을 합치지 않기 위한 식별자입니다.
3. 현재 정책/API가 확인되지 않은 경우 작업은 **연결/정책 확인 필요** 상태로 남고 HTTP 요청을 시작하지 않습니다.
4. 확인된 후보를 기존 로컬 인물/그룹에 연결하거나 새로 등록합니다. 소속 변경은 제안으로 보존하고 사용자의 수정 사항을 덮어쓰지 않습니다.
5. 확인된 Commons 카테고리가 있는 대상만 사진 목록을 수집합니다. 이름 검색만으로 사진을 인물에게 귀속시키지 않습니다.
6. 온라인 사진 선택 시 조건에 맞는 썸네일을 받고, **선택 원본 보관** 시 원본을 다운로드합니다. 인물의 실제 등장은 별도로 확인해야 합니다.

정책 검증은 개발/관리 절차입니다. `python scripts/check_sources.py`로 원문과 체크섬, vocabulary ID를 확인할 수 있습니다. 원문·robots·API 사용 범위·파일별 라이선스·User-Agent 요구를 실제로 읽고 검토한 뒤에만 `python scripts/check_sources.py --record-review --review-note "실제로 검토한 내용"`으로 로컬 검증 기록을 남깁니다. 원문 다운로드만으로 이용 조건에 동의하거나 사용권이 확보되었다고 간주하지 않습니다. 이 클라우드의 네트워크 변경은 환경 설정에서 검토/저장 후 게시해야 적용됩니다.

신규 발견 커버리지는 제한적입니다. Wikidata의 K-pop 장르/유형/성별/소속/활동 정보가 빠지면 발견되지 않거나 검토 대기로 남습니다. 2012년 이후는 자동 등록 규칙의 운영상 기준이며 공식 세대 판정이 아닙니다. 확인되지 않은 사진의 성별/등장 인물을 AI로 추정해 걸러내지 않습니다. 대량 수집과 모든 아티스트/사진의 완전 수집을 보장하지 않습니다. AI 분석·업스케일은 여전히 미구현이며 이미지의 AI 사용권을 부여하지 않습니다.

## DB 업데이트

v0.5.0은 스키마 v4를 사용합니다. 기존 v1/v2/v3 DB는 SQLite backup API로 버전별 백업을 남긴 뒤 원자적으로 추가 테이블을 생성합니다. 기존 그룹/인물/사진/즐겨찾기/설정은 유지합니다. 업데이트 전 앱을 닫고 데이터 폴더를 별도 백업하세요. 이전 앱으로 새 v4 DB를 열 수는 없습니다.

최적화: 256개 단위 비동기 조회, 모델/델리게이트 기반 리스트, batched 레이아웃, 화면 주변 썸네일 우선, 최대 8개 썸네일 작업/2개 처리 스레드, decoded thumbnail LRU 96개, 뷰어 이전 작업 취소와 오래된 응답 무시. 메타데이터 캐시는 최대 2,048건, 뷰어 메타데이터 창은 최대 768건, 디코딩 이미지 캐시는 128MiB/12항목입니다. Qt 내부 레이아웃 데이터는 전체 결과 수에 비례하며 현재 표시 이미지와 디코더 임시 버퍼는 이미지 캐시 한도에 포함되지 않습니다. PNG 등은 미리보기에서도 내부적으로 전체 이미지를 디코딩할 수 있습니다. 파일 영역 단위 디코딩과 디스크 캐시 용량 자동 정리는 아직 지원하지 않습니다.

## 멀티 소스 기반 사용

온라인 → **출처 · URL**에서 검토한 출처 설정과 HTTPS 링크를 등록합니다. 링크 등록은 다운로드 허용을 의미하지 않습니다. 메타데이터, 썸네일, 원본, 로컬 분석, AI 입력, 결과 저장 권한은 각각 별도로 검토합니다. 브라우저 DOM 렌더링도 추가 허용이 필요합니다. JSON 설정 예시는 `docs/examples/public-page-source.json`에 있습니다. 외부 실행 코드는 가져오지 않습니다.

정적 HTML/직접 이미지 URL은 기본 의존성으로 동작합니다. 선택적 JavaScript DOM 처리는 별도 브라우저가 필요합니다:

```sh
python -m pip install -r requirements-browser.lock
python -m playwright install chromium
```

브라우저 샌드박스를 해제하지 마세요. Windows 배포 스크립트는 선택 브라우저를 자동 포함하지 않습니다. 실제 사이트 정책/도메인/파일 권한 검토 전에는 활성화하지 않습니다. X·Instagram·언론사·Flickr·Kpopping 등은 현재 검토 후보이며 전용 수집 구현 또는 실제 연동 완료를 뜻하지 않습니다.

검증: Linux에서 실제 Chromium 샌드박스를 유지한 합성 DOM 테스트를 포함해 103개 통과. 10만 건 가상 메타데이터 마지막 페이지 이동 13.16ms, 메타데이터 상주 최대 2,048건. 고유 사진 10만 장 디코딩이나 Windows 화면 FPS 측정은 아닙니다.

## 연관 사진과 인물 참조 후보

- 사진 우클릭 → **이 사진과 연관된 사진 찾기**, 또는 정보 패널의 **연관 사진 찾기**를 사용합니다. 뷰어의 **연관 사진**에서도 열 수 있습니다.
- 확인된 인물 연결, 기록된 촬영일/게시일, 그룹, 출처 페이지와 이미 허용되어 계산된 유사 특징으로 후보를 찾습니다. 관계마다 이유를 표시하며 규칙 점수는 확률이나 복원 품질이 아닙니다.
- **동일 행사로 확인 / 연관 사진으로 연결 / 이 관계 제외**에서 근거를 기록합니다. 확인/제외는 양방향이며 원본이나 인물 연결을 변경하지 않습니다. **수동 관계 해제**는 이 기록만 제거합니다.
- 뷰어의 **미리보기**는 연관 사진 필름스트립입니다. 기본은 숨김, 최대 12장, 한 장씩 비동기 로딩합니다. 더블클릭하면 해당 사진의 연관 근거와 목록을 엽니다.
- **권한 확인된 인물 참조 후보** 모드에서 실제 등장이 확인된 인물을 선택합니다. 기준 사진과 후보 모두 로컬 분석·AI 입력 권한이 필요합니다. 후보의 표시 권한도 별도로 검사합니다.
- 직접 권리를 확인한 로컬 사진은 **기준 사진 권한 / 선택 사진 권한**에서 기록합니다. 다른 사진의 개별 권한은 자동 허용되지 않습니다. 원격 출처는 기존 **온라인 → 출처 · URL**에서 검토합니다.

현재 검색 대상은 로컬에 등록·보관된 사진입니다. 저장하지 않은 원격 후보까지 통합한 사진 벽은 후속 작업입니다. 후보 수를 제한한 인덱스 검색이므로 전체 자료에서 최적의 참조를 찾는다는 보장은 없습니다. 얼굴 크기·각도·선명도, 의상/배경 의미와 정체성 보존은 평가하지 않습니다. AI 복원·업스케일과 3중 비교도 아직 실행할 수 없습니다.
